- LOOK (decided 2026-11-18, user's reference = dense coloured point-cloud scan in black void): game renders the city as point cloud by default (`web/js/pointcloud.js`; `?mesh` or key P = old mesh view, O = occlusion prepass, B = back-faces). Data: `pipeline/pointcloud/bl_sample.py` (in Blender: samples every manifest GLB → `data/pointcloud/stage/*.npz`, git-ignored, ~8 GB) + `bl_tile.py` (32 m tiles, shuffled so rank = uniform subsample, 12 B/pt, `_a` coarse 12 % / `_b` fine) → `web/assets/city/pointcloud/` (~107 M pts, 1.3 GB – mind LFS quota). Density by player distance via rank < f(d); occluders/scan blockers = collision geometry (small furniture colliders excluded). F-scan: distance cubemap from player → everything in line of sight shown dense for 10 s, walkable ground tinted blue/yellow/red.
- Look v2 (user, 2026-11-18): view range only ~10 m (full density to 6.5 m, black beyond) → player must scan with F regularly; small points; realism via lighting BAKED IN BLENDER: `pipeline/pointcloud/bl_light.py` (one 14 M-tri occluder mesh "PC_Verdecker", Geometry-Nodes Raycast per point: sun shadow + 6 AO + 4 sky rays, ~4.5 min for 292 M pts) writes lit sRGB into the tiles; index.json "baked" → shader skips Lambert. Tiles now at full sampling density (no thinning, 3.3 GB). Order: bl_sample → bl_tile → bl_light (re-run bl_light after every bl_tile). User gets annoyed by questions/check-backs: just implement.
- Perf (2026-11-19): tiles are ordered in 8-m cells (`bl_tile.cellify`, index tile["cells"]); renderer makes one Points object per cell sharing the buffers and only draws cells in view radius; point mode loads collision files only (`world.load({collisionOnly})`), P reloads with `?mesh`. Esc = options menu (view range, densify passes, point size, exposure, resolution, "Zum Startbildschirm"). Point-cloud tiles are git-ignored (3.3 GB > LFS quota); clones regenerate via `blender -b --factory-startup -P pipeline/pointcloud/run_headless.py`, without them the game falls back to mesh view.
